# 🎯 OKRs e KPIs - Documentação Completa

## 📖 O que são OKRs e KPIs?

### OKR (Objectives and Key Results)
**Objetivos e Resultados-Chave** - Define ONDE você quer chegar em 3 meses.

- **Objective (Objetivo)**: Meta ambiciosa e inspiradora
- **Key Results (Resultados-Chave)**: 3-5 métricas mensuráveis que provam que você alcançou o objetivo

**Características:**
- ⏰ **Trimestral** (90 dias)
- 🎯 **Ambicioso** (70-80% de alcance já é sucesso)
- 📊 **Mensurável** (sempre com números)
- 🎨 **Inspirador** (te motiva a acordar e trabalhar)

### KPI (Key Performance Indicator)
**Indicador-Chave de Performance** - Mede se você está no CAMINHO CERTO.

- **Métricas contínuas** que você acompanha semanalmente
- Mostram se seus esforços diários estão levando aos OKRs
- São o "combustível" dos OKRs

**Características:**
- ⏰ **Contínuo** (mede toda semana)
- 📈 **Operacional** (ações do dia a dia)
- 🎯 **Específico** (fácil de medir)
- ⚡ **Acionável** (você controla o resultado)

### 🎯 KPIs de Produtividade (medem ESFORÇO)

#### KPI 1: Horas código prático/semana
- **Meta**: 12-15h
- **Como mede**: Notion "Hours This Week" → Categoria "Projetos"
- **Por que importa**: Prática é o que te torna desenvolvedor
- **Red flag**: < 10h por semana
- **Fonte de dados**: Database "Hours This Week"

**Exemplo de semana ideal:**
- Seg/Qua: 1.5h cada = 3h
- Ter/Qui/Sex: 2.5h cada = 7.5h
- Sáb/Dom: 2h cada = 4h
- **Total: 14.5h** ✅

#### KPI 2: Horas estudo teórico/semana
- **Meta**: 5-8h
- **Como mede**: Notion "Hours This Week" → Categoria "Estudos"
- **Por que importa**: Base conceitual sólida
- **Red flag**: < 4h por semana
- **Fonte de dados**: Database "Hours This Week"

**O que conta como teoria:**
- Assistir aulas do curso HashTag
- Ler livro de Algoritmos
- Ler documentação oficial
- Estudar conceitos (closures, promises, etc)

#### KPI 3: Horas inglês/semana
- **Meta**: 3-5h
- **Como mede**: Notion "Hours This Week" → Categoria "Idiomas"
- **Por que importa**: Habilidade multiplicadora
- **Inclui**: Aulas presenciais (2×50min) + estudo em casa
- **Fonte de dados**: Database "Hours This Week"

**Breakdown:**
- Aulas presenciais: 1h40min
- Leitura artigos: 1h
- Vídeos técnicos: 1h
- Worksheets: 1h
- **Total: 4h40min** ✅

#### KPI 4: Dias estudados/semana
- **Meta**: 6-7 dias
- **Como mede**: Notion "Hour Tracker" → Count unique dates
- **Por que importa**: Consistência > intensidade
- **Red flag**: < 5 dias
- **Fonte de dados**: Database "Hour Tracker"

**Regra:**
- Qualquer dia com pelo menos 1h registrada conta
- Ideal: estudar todos os dias, mesmo que pouco

#### KPI 5: Streak dias consecutivos
- **Meta**: Sempre aumentando
- **Como mede**: Calculado automaticamente pelo dashboard
- **Por que importa**: Forma hábitos sólidos
- **Recompensa**: Cada 7 dias = 1 semana streak 🔥
- **Fonte de dados**: Database "Hour Tracker" (dates sequenciais)

### 💻 KPIs de Prática (medem RESULTADOS)

#### KPI 6: Commits GitHub/semana
- **Meta**: 20-30 commits
- **Como mede**: GitHub API ou registro manual no Notion
- **Por que importa**: Mostra atividade constante
- **Red flag**: < 15 commits
- **Fonte de dados**: GitHub API (futura integração) ou Notion manual

**Dica:**
- Commits pequenos e frequentes > commits gigantes
- Mensagens claras: "feat: add product filter" > "update"

#### KPI 7: Features concluídas/semana
- **Meta**: 3-5 features
- **Como mede**: Notion "Task Panel" → Status "Complete"
- **Por que importa**: Entrega de valor
- **Red flag**: < 2 features
- **Fonte de dados**: Database "Task Panel"

**O que é uma feature:**
- Painel de admin
- Sistema de filtros
- Página de detalhes
- Botão de compartilhar
- etc.

#### KPI 8: Bugs resolvidos/semana
- **Meta**: 5-8 bugs
- **Como mede**: Registro manual no Notion
- **Por que importa**: Capacidade de debug
- **Fonte de dados**: Novo campo no Notion "Bugs Resolved"

**Sugestão:**
- Crie propriedade "Type" na database Tasks
- Opções: Feature | Bug | Refactor | Docs
- Filtre por Type = Bug + Status = Complete

#### KPI 9: PRs criados/mês
- **Meta**: 2-4 PRs
- **Como mede**: GitHub profile
- **Por que importa**: Colaboração + visibilidade
- **Red flag**: 0 PRs no mês
- **Fonte de dados**: GitHub API

**Tipos de PR:**
- Contribuição open source
- Code review em projetos de amigos
- PRs internos em projetos pessoais (boa prática)

#### KPI 10: Projetos finalizados/trimestre
- **Meta**: 2 projetos
- **Como mede**: Notion "Projects" → Status "Concluído"
- **Por que importa**: Portfólio tangível
- **Red flag**: 0 projetos finalizados no trimestre
- **Fonte de dados**: Database "Active Projects"

**Critério para "finalizado":**
- ✅ Deploy em produção
- ✅ README completo
- ✅ Código no GitHub
- ✅ Funcionalidades principais operando

## 📈 Como usar OKRs e KPIs juntos

### Fluxo semanal:

**Segunda-feira (início da semana):**
1. Revise OKRs trimestrais
2. Defina metas da semana baseadas nos KRs
3. Planeje como vai atingir KPIs

**Diariamente:**
- Registre horas no Notion
- Faça commits constantes
- Marque tasks como concluídas

**Domingo (revisão semanal):**
1. Calcule todos os KPIs
2. Compare com metas
3. Identifique o que melhorar
4. Atualize progresso dos OKRs

**Mensalmente (1º dia do mês):**
1. Relatório completo de KPIs
2. Progresso dos OKRs (%)
3. Ajustes de rota se necessário

**Trimestralmente (final de Março):**
1. Review completo dos OKRs
2. Celebre conquistas (mesmo 70% é sucesso!)
3. Defina novos OKRs para Q2

## ⚠️ Red Flags (alertas de atenção)

Se isso acontecer, PARE e reflita:

### 🚨 Crítico (ação imediata):
- ❌ 2+ dias sem estudar seguidos
- ❌ Horas semanais < 15h
- ❌ 0 commits na semana
- ❌ 0 features entregues em 2 semanas

### ⚠️ Atenção (revisar estratégia):
- 🟡 3+ KPIs abaixo da meta
- 🟡 OKR progress < 20% (após 1 mês)
- 🟡 Muitas horas de teoria, pouca prática
- 🟡 Muita prática, zero teoria

### ✅ Sinais positivos:
- 🟢 Todos KPIs > 80% da meta
- 🟢 Streak > 7 dias
- 🟢 OKR progress > 30% (após 1 mês)
- 🟢 Equilíbrio entre teoria e prática
